# SteelSeries Headsets for Omarchy

SteelSeries USB headset integration for the Omarchy Quattro shell. The plugin
uses HeadsetControl to detect the model and its available controls. The Arctis
Nova 7X (`1038:22a5`) has been tested on hardware. Other models depend on their
[HeadsetControl support](https://github.com/Sapd/HeadsetControl#supported-devices)
and need hardware validation.

- Headset power / link status, battery percentage and charging indicator where reported.
- Two stereo outputs: **SteelSeries Game** and **SteelSeries Chat**.
- A readable ChatMix wheel balances the two outputs, with both full at center. Headsets with separate native Game and Chat sinks use those sinks and their own hardware mixer.
- Separate Game and Chat volume trims; normal volume keys remain usable.
- All volume sliders apply during dragging (50 ms updates), with the final level applied immediately on release. Pending changes are coalesced to avoid replaying stale volume levels.
- Remember application assignments; Discord, Vesktop, Zoom and communication-role streams default to Chat.
- Low battery alert at 20%, optional.
- Choose another output for Game/Chat while the headset is off; automatically return to the headset when it turns on. The choice is saved, and no output is selected automatically.
- Send sidetone and idle shutoff settings when the model supports them. Each successful choice is saved per USB model and marked with a check, including after reopening the panel or restarting the shell. Checkmarks show the last setting applied by the plugin. Opening the panel does not resend settings.

Connect via USB or the wireless receiver in PC/USB mode. When multiple supported
models are plugged in, the plugin keeps its selected model until that receiver
is unplugged. Connect only one receiver per USB product ID because HeadsetControl
addresses devices by that ID. Models without readable ChatMix still get separate
software volume controls and app routing. App rules apply to streams already
using the headset or its virtual outputs. Browser tabs share an app assignment.
Batteries, hardware controls and automatic power-off detection depend on the
model. Direct Bluetooth connections and analog jacks have no USB controls.

## Dependencies

Python 3, `pipewire`, `pipewire-pulse` (`pactl`, `pw-loopback`), `hidapi`, and [HeadsetControl](https://github.com/Sapd/HeadsetControl) with JSON capabilities discovery and support for your receiver. `notify-send` is optional. No network requests are made at runtime.

An installed `headsetcontrol` on PATH takes precedence. For a manual install, build the separate GPL dependency from upstream and install it under `~/.local/lib/omarchy-steelseries/`.

```sh
git clone https://github.com/Sapd/HeadsetControl.git
cd HeadsetControl
git checkout 0c8a76fa019cd02263a1c69e00e18e229b16d87f
cmake -S . -B build -DBUILD_UNIT_TESTS=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8
install -Dm755 build/headsetcontrol ~/.local/lib/omarchy-steelseries/headsetcontrol
```

Use the udev rules from your HeadsetControl package for access to other supported receivers. For a manual build, use the upstream rules generated by `headsetcontrol --udev`. The bundled `70-omarchy-steelseries.rules` is a narrower alternative for the Nova 7X alone. It grants the active local seat access to interface 03 of `1038:22a5`.

```sh
sudo install -m644 70-omarchy-steelseries.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
```

Reconnect the receiver, or trigger a change event for its control hidraw node to apply without reconnecting. The plugin never runs as root.

## Install locally

The plugin uses the ID `acrogenesis.arctis` so existing bar layouts and
saved audio routes carry over.

Clone [acrogenesis/omarchy-steelseries](https://github.com/acrogenesis/omarchy-steelseries) and copy it to `~/.config/omarchy/plugins/acrogenesis.arctis`, then:

```sh
omarchy plugin validate ~/.config/omarchy/plugins/acrogenesis.arctis
omarchy-shell shell rescanPlugins
omarchy plugin enable acrogenesis.arctis --section right --before omarchy.audio
```

Click the headphones icon and choose **Use SteelSeries Game as default output**. Existing headset playback moves to Game (communication apps to Chat). You can also select SteelSeries Chat directly inside voice apps. Application assignments and volume trims are stored in `~/.config/omarchy/arctis/config.json`.

The shell owns one backend process for all monitors. It polls headset status four times per second while connected, and audio/app state every two seconds. When disabled, it moves virtual playback back to the physical headset, restores the previous default if a virtual output is still selected, and removes its virtual outputs. When enabled again it resumes the Game default if previously requested and either the physical headset or saved alternate output is selected. Selecting another physical output while running is respected. Reconnection recreates the virtual outputs without restarting PipeWire.

## Diagnostics and tests

```sh
omarchy-shell acrogenesis.arctis status
python3 arctis.py --command '{"action":"status"}'
python3 -m unittest discover -s tests -v
node tests/test_panel.js # optional development check for dropdown label safety
node tests/test_volume_queue.js
QT_QPA_PLATFORM=offscreen /usr/lib/qt6/bin/qmltestrunner -input tests/qml
```

The user-only runtime socket is `$XDG_RUNTIME_DIR/omarchy-steelseries.sock`; it accepts bounded JSON commands. No audio is recorded. A failed HID query shows an error and unknown wheel position; battery can still come from the kernel. It never turns a failed read into a 0% battery reading.

The USB receiver stays present when some wireless headsets are off. An explicit offline response clears the displayed battery and wheel state. The kernel's cached capacity is ignored when its power status is Unknown. Models without battery reporting show USB presence. Automatic fallback on wireless power-off requires a model that reports its offline state.

An unplugged USB receiver is shown as **Receiver disconnected**, separately from an off headset or an unavailable status query. The selected alternate output remains usable with the receiver unplugged. USB presence is checked independently of the headset's audio profile and HID permissions.

The compact main panel shows status, Game/Chat volume rows and a **When headset is off** dropdown. While the alternate output is active, an **Output** volume row controls that device's actual volume independently of Game/Chat. It follows volume changes made in other mixers; PipeWire owns the device volume. **Applications** expands app routing; **More settings** expands wheel-following, sidetone, inactivity and battery alerts. These sections fold again when you close the panel; saved settings remain unchanged.

Use **When headset is off** to choose your speakers or monitor output. Both virtual outputs route there while the headset is off, preserving application assignments and independent volume trims. The hardware wheel does not attenuate the alternate output. Turn the headset on to resume hardware mixing. A transient unknown power reading keeps an active alternate route; an unavailable selected output is reported without choosing a different device. **Don't switch outputs** disables this behavior. The normal system default can remain SteelSeries Game; its actual playback destination changes. Disabling the plugin while an alternate output is active moves playback to that output.

## Next ideas

- ChatMix on-screen display while turning the wheel in games.
- Per-game profiles and automatic app assignments from Steam game identity.
- Separate music/media bus and optional voice ducking.
- Software EQ presets (flat/music/footsteps), limiter and microphone noise suppression through PipeWire or EasyEffects. Hardware EQ on this updated firmware needs separate validation before exposing it.
- Connection notifications when the headset turns on or off.
- Battery history and a runtime estimate once enough discharge samples exist.

Firmware updates remain the responsibility of SteelSeries GG; this plugin does not flash firmware.
